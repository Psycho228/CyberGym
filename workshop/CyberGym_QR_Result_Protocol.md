# CyberGym Workshop QR Result Protocol v1

Этот документ фиксирует контракт между картой CS2 Workshop и Android-приложением CyberGym.

## Пользовательский сценарий

1. Пользователь запускает тренировку в CyberGym.
2. Выполняет все упражнения на карте Workshop.
3. Карта показывает итоговый QR-код.
4. В приложении пользователь нажимает «Завершить тренировку».
5. Приложение сканирует код и показывает распознанные показатели.
6. Пользователь при необходимости редактирует значения.
7. По кнопке «Подтвердить и завершить» результаты сохраняются в Supabase, начисляется XP, сессия закрывается.

Один `run_id` разрешено сохранить только один раз для одного пользователя.

## Формат содержимого QR

Рекомендуемый формат:

```text
CYBERGYM1:<base64url без padding от UTF-8 JSON>
```

Для разработки приложение также принимает чистый JSON без префикса и Base64.

Исходный JSON:

```json
{
  "v": 1,
  "source": "cybergym_workshop",
  "map": "cybergym_training_hub",
  "run_id": "cg-1722168000-8f31a2",
  "completed_at": "2026-07-28T12:00:00Z",
  "results": [
    {
      "exercise": "counter_strafe",
      "metrics": {
        "attempts": 50,
        "successful_stops": 43,
        "hits": 40,
        "accuracy": 80,
        "avg_stop_speed": 18.4,
        "score": 86
      }
    }
  ]
}
```

## Обязательные поля

| Поле | Тип | Назначение |
|---|---|---|
| `v` | integer | Версия протокола. Для MVP — `1`. |
| `source` | string | Всегда `cybergym_workshop`. |
| `map` | string | Техническое имя карты. |
| `run_id` | string | Уникальный ID одного прохождения карты. |
| `results` | array | Результаты всех упражнений текущей тренировки. |
| `results[].exercise` | string | `slug` упражнения из таблицы `exercises`. |
| `results[].metrics` | object | Непустой набор показателей упражнения. |

`completed_at` необязателен. Если карта не умеет получать корректное UTC-время, поле можно не передавать. Сервер всё равно сохранит собственное время подтверждения.

Значения внутри `metrics` должны быть простыми JSON-типами: число, строка или boolean. Вложенные массивы и объекты в версии 1 не используются.

## Канонические коды MVP

| Упражнение | `exercise` |
|---|---|
| Быстрые флики | `warmup_flicks` |
| Только хедшоты | `aim_headshots` |
| Контроль AK-47 | `ak_spray` |
| Counter-strafe | `counter_strafe` |

QR дневного плана обязан содержать результат каждого упражнения, открытого в приложении. Порядок элементов не важен: сопоставление выполняется по `exercise`.

## Рекомендуемые метрики STRAFE50

```json
{
  "attempts": 50,
  "successful_stops": 43,
  "hits": 40,
  "left_attempts": 25,
  "right_attempts": 25,
  "avg_stop_speed": 18.4,
  "best_stop_speed": 2.1,
  "accuracy": 80,
  "score": 86
}
```

Скорость остановки и результат выстрела должны храниться отдельно. Попадание не означает качественный counter-strafe, а хорошая остановка не гарантирует попадание.

## Генерация `run_id`

ID должен меняться при каждом новом старте зоны или полного тренировочного маршрута. Практичный формат:

```text
cg-<unix_time>-<6 случайных hex-символов>
```

Пример:

```text
cg-1785240000-8f31a2
```

Если карта не имеет надёжного источника времени, достаточно случайного значения длиной 16–32 символа, сгенерированного заново для каждого прохождения.

## Проверки приложения и сервера

Приложение отклоняет QR, если:

- это не протокол CyberGym v1;
- отсутствуют результаты;
- есть неизвестные или пропущенные упражнения;
- упражнения повторяются;
- метрики пусты или имеют неподдерживаемую структуру.

Supabase дополнительно проверяет:

- соответствие `exercise` реальному упражнению сессии;
- принадлежность сессии авторизованному пользователю;
- размер payload не более 64 КБ;
- одноразовое использование `run_id`;
- идемпотентное начисление XP.

Результат остаётся пользовательским вводом: его можно отредактировать, поэтому этот протокол не является античитом и не должен использоваться для соревновательных рейтингов или денежных наград.

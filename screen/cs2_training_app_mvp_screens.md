# CS2 Training App — MVP Screen Specification

## 1. Цель документа

Документ описывает экраны мобильного MVP приложения для русскоязычных игроков CS2 уровня Premier / FACEIT 3–7.

Главная задача приложения: помочь игроку регулярно выполнять персональный тренировочный трек длительностью 20–40 минут в день и видеть прогресс.

## 2. Основная навигация

Нижняя навигация состоит из четырёх разделов:

1. **Сегодня**
2. **Трек**
3. **Прогресс**
4. **Профиль**

Экран «Достижения» не рекомендуется выносить в отдельную вкладку MVP. Достижения являются частью раздела «Прогресс».

Дополнительные экраны открываются поверх основной навигации:

- упражнение;
- результат тренировки;
- AI-ассистент;
- уведомления;
- paywall;
- настройки;
- onboarding и диагностика.

# 3. Экраны MVP

## 3.1. Splash Screen

### Назначение

Показать бренд во время загрузки приложения и проверки авторизации.

### Содержимое

- логотип;
- название приложения;
- индикатор загрузки.

### Логика

Приложение проверяет:

- авторизован ли пользователь;
- завершён ли onboarding;
- есть ли активный тренировочный трек.

### Переходы

- новый пользователь → Welcome;
- onboarding не завершён → последний незавершённый шаг;
- активный пользователь → Сегодня.

---

## 3.2. Welcome

### Назначение

Объяснить основную ценность продукта и начать onboarding.

### Содержимое

- короткий заголовок;
- описание: персональный тренировочный трек для роста Premier / FACEIT;
- три преимущества:
  - тренировки по 20–40 минут;
  - программа под уровень и слабые навыки;
  - контроль прогресса;
- кнопка «Начать»;
- кнопка «У меня уже есть аккаунт».

### Основное действие

`Начать`

---

## 3.3. Авторизация

### Назначение

Создать аккаунт или войти.

### Варианты

- Telegram;
- email;
- Google, если доступно в выбранной дистрибуции.

### Требования

- минимальное количество полей;
- согласие с политикой конфиденциальности;
- возможность продолжить onboarding после перезапуска приложения.

---

## 3.4. Выбор игровой платформы

### Назначение

Определить основной источник рейтинга и статистики.

### Варианты

- FACEIT;
- Premier;
- играю в обоих режимах.

### Логика

Для FACEIT пользователь подключает профиль.

Для Premier пользователь вводит рейтинг вручную.

Если выбраны оба режима, пользователь указывает основной режим для текущей цели.

---

## 3.5. Подключение FACEIT / ввод Premier

### Назначение

Получить исходные данные игрока.

### FACEIT

- поле nickname или ссылка на профиль;
- найденный профиль;
- аватар;
- текущий уровень;
- ELO;
- кнопка подтверждения.

### Premier

- текущий рейтинг;
- количество матчей в неделю;
- дата последнего изменения рейтинга;
- необязательное поле Steam ID.

### Ошибки

- профиль не найден;
- API временно недоступен;
- профиль найден неверно;
- пользователь может пропустить подключение и продолжить вручную.

---

## 3.6. Цель

### Назначение

Зафиксировать измеримую цель пользователя.

### Поля

- текущий рейтинг;
- желаемый рейтинг;
- основной режим: Premier или FACEIT;
- желаемый срок:
  - 14 дней;
  - 30 дней;
  - без конкретного срока.

### Примечание

Приложение не гарантирует достижение рейтинга. Цель используется для выбора интенсивности и визуализации прогресса.

---

## 3.7. Настройки тренировок

### Назначение

Собрать ограничения для персонального трека.

### Поля

- длительность занятия:
  - 20 минут;
  - 40 минут;
- дней в неделю:
  - 3;
  - 4;
  - 5;
- предпочитаемое время;
- доступные инструменты:
  - CS2 workshop-карты;
  - Aimlabs;
  - practice mode;
  - реальные матчи;
- основные карты;
- роль или стиль игры, если пользователь знает.

### MVP-карты

- Mirage;
- Dust II.

---

## 3.8. Самооценка навыков

### Назначение

Получить первичный субъективный профиль.

### Навыки

- aim;
- recoil;
- movement;
- counter-strafing;
- crosshair placement;
- utility;
- знание карт;
- выбор позиций;
- уверенность в дуэлях.

### Формат

Для каждого навыка шкала:

- слабая сторона;
- нестабильно;
- нормально;
- сильная сторона;
- не знаю.

### Требование

Самооценка не должна быть единственным источником персонализации.

---

## 3.9. Benchmark

### Назначение

Получить объективную стартовую точку.

### Содержимое

Набор из 3–5 коротких тестов общей длительностью до 10 минут.

Примеры:

- micro-adjustment;
- recoil;
- counter-strafing;
- prefire;
- quiz по карте.

### Для каждого теста

- краткая инструкция;
- ссылка или способ запуска;
- поле результата;
- пример правильного формата результата;
- возможность отметить «не получилось запустить».

### Результат

После завершения формируется первичный профиль навыков.

---

## 3.10. Результат диагностики

### Назначение

Показать пользователю, что приложение поняло его ситуацию.

### Содержимое

- уровень игрока;
- две приоритетные зоны развития;
- одна сильная сторона;
- рекомендуемая частота занятий;
- краткое объяснение выбора;
- ожидаемый фокус первого трека.

### Пример

> Главные приоритеты: counter-strafing и crosshair placement.  
> Aim находится на достаточном уровне, но часть дуэлей проигрывается из-за стрельбы до полной остановки.

### Основное действие

`Сформировать мой трек`

---

# 4. Основные вкладки

## 4.1. Сегодня

### Назначение

Главный экран приложения. Пользователь должен за несколько секунд понять, что ему делать сегодня.

### Верхний блок

- приветствие;
- текущий день трека;
- недельный прогресс;
- серия занятий;
- кнопка уведомлений.

### Главная карточка

- название сегодняшней тренировки;
- общая длительность;
- основной навык;
- количество упражнений;
- кнопка «Начать тренировку».

### Список заданий

Каждое задание показывает:

- название;
- тип;
- длительность;
- навык;
- статус:
  - не начато;
  - выполняется;
  - выполнено;
  - пропущено.

### Match Focus

Отдельная карточка с одной установкой для реального матча.

Пример:

> Сегодня перед каждым первым выстрелом проверяй полную остановку персонажа.

Действия:

- «Возьму в следующий матч»;
- «Отметить результат».

### AI-ассистент

Компактная кнопка или карточка:

- «У меня только 15 минут»;
- «Объясни сегодняшнюю тренировку»;
- «Замени упражнение»;
- «Задать вопрос».

### Состояния

- тренировка не начата;
- тренировка в процессе;
- тренировка завершена;
- день отдыха;
- пользователь пропустил несколько дней;
- трек завершён.

### Главное действие

`Начать / продолжить тренировку`

---

## 4.2. Экран упражнения

### Назначение

Провести пользователя через одно конкретное мини-задание.

### Содержимое

- название;
- развиваемый навык;
- длительность;
- короткое видео;
- текстовая инструкция;
- что запустить на компьютере;
- критерий выполнения;
- фокус внимания;
- типичная ошибка;
- таймер или счётчик подходов.

### Действия

- начать;
- пауза;
- завершить;
- не могу запустить;
- слишком легко;
- слишком сложно;
- заменить упражнение.

### Ограничение мобильного MVP

Приложение не должно утверждать, что автоматически подтвердило выполнение, если данные введены пользователем вручную.

---

## 4.3. Результат упражнения

### Назначение

Зафиксировать выполнение и собрать данные для адаптации.

### Поля

- результат;
- субъективная сложность от 1 до 5;
- получилось ли удерживать фокус;
- необязательный комментарий;
- проблема при запуске.

### Быстрые ответы

- слишком легко;
- нормально;
- слишком сложно;
- не понял упражнение;
- не увидел пользы.

### Логика

Результат влияет на:

- сложность следующих упражнений;
- повторение задания;
- недельный отчёт;
- рекомендации AI.

---

## 4.4. Итог тренировки

### Назначение

Закрыть ежедневный цикл и подготовить перенос навыка в матч.

### Содержимое

- выполненное время;
- выполненные задания;
- основной результат;
- прогресс недели;
- Match Focus;
- рекомендация следующего занятия.

### Действия

- «Я пойду играть»;
- «Завершить день»;
- «Обсудить с AI».

### После матча

Пользователь может ответить на короткие вопросы:

- удалось ли применять фокус;
- насколько уверенно чувствовал себя в матчах;
- что мешало;
- оценка от 1 до 5.

---

## 4.5. Трек

### Назначение

Показать пользователю его текущую программу и ближайшее будущее.

### Верхний блок

- название трека;
- цель;
- даты;
- прогресс;
- текущий фокус;
- число завершённых занятий.

### Таймлайн

Дни или недели отображаются последовательно:

- выполнено;
- сегодня;
- запланировано;
- контрольная точка;
- отдых;
- заблокировано тарифом.

### Карточка недели

- цель недели;
- развиваемые навыки;
- количество тренировок;
- benchmark или контрольная точка;
- ожидаемая нагрузка.

### Доступные действия

- открыть будущий день без возможности выполнить раньше времени;
- изменить длительность занятий;
- изменить тренировочные дни;
- поставить трек на паузу;
- завершить трек;
- начать новый трек после завершения.

### Важный принцип

Будущие задания можно показывать кратко, но подробная программа может корректироваться после результатов текущей недели.

---

## 4.6. Прогресс

### Назначение

Показать доказательства регулярности и изменения навыков.

### Блок «Общий прогресс»

- количество тренировок;
- тренировочное время;
- текущая серия;
- процент выполнения плана;
- завершённые треки.

### Блок «Навыки»

Список навыков с текущим состоянием:

- требует внимания;
- развивается;
- стабильно;
- сильная сторона.

Для каждого навыка:

- динамика;
- связанные упражнения;
- дата последней проверки;
- источник оценки:
  - benchmark;
  - FACEIT;
  - самооценка;
  - результаты тренировок.

### Блок «Рейтинг»

- текущий FACEIT ELO / Premier;
- стартовое значение;
- динамика;
- дата обновления;
- предупреждение, что рейтинг является шумной метрикой.

### Блок «Достижения»

Примеры:

- первая тренировка;
- четыре тренировки за неделю;
- семь дней регулярности;
- завершён первый трек;
- улучшен benchmark;
- изучено пять utility;
- выполнено десять match missions.

### Блок «История»

- список тренировок;
- недельные отчёты;
- результаты benchmark;
- изменения программы.

### Главное действие

`Открыть недельный отчёт`

---

## 4.7. Достижение — детальный экран

### Назначение

Показать смысл достижения и усилить мотивацию.

### Содержимое

- название;
- иллюстрация или иконка;
- дата получения;
- условие;
- связанная статистика;
- следующий уровень достижения;
- возможность поделиться.

### Ограничение

Достижения не должны заменять реальный прогресс или превращать приложение в систему бессмысленных наград.

---

## 4.8. Недельный отчёт

### Назначение

Объяснить, что изменилось и почему программа корректируется.

### Содержимое

- выполнено тренировок;
- план / факт;
- время;
- лучший результат;
- сложные упражнения;
- динамика benchmark;
- доступная динамика FACEIT;
- субъективная оценка переноса в матч;
- вывод системы;
- изменения следующей недели.

### Пример вывода

> Ты стабильно выполнял упражнения на movement, но результат recoil остаётся нестабильным. На следующей неделе нагрузка на movement уменьшается, а recoil получает дополнительное короткое занятие.

### Основное действие

`Продолжить следующую неделю`

---

## 4.9. Профиль

### Назначение

Управлять игровыми данными, целью, подпиской и настройками приложения.

### Верхний блок

- аватар;
- nickname;
- FACEIT level;
- Premier rating;
- активный тариф.

### Раздел «Игровой профиль»

- связанный FACEIT;
- Steam ID;
- любимые карты;
- роль;
- количество матчей в неделю;
- текущая цель;
- изменить цель.

### Раздел «Настройки тренировок»

- 20 или 40 минут;
- количество дней;
- время напоминаний;
- доступные сервисы;
- дни отдыха.

### Раздел «Подписка»

- текущий тариф;
- доступные функции;
- управление подпиской;
- восстановить покупку;
- промокод.

### Раздел «Приложение»

- уведомления;
- язык;
- политика конфиденциальности;
- пользовательское соглашение;
- поддержка;
- сообщить о проблеме;
- удалить аккаунт;
- выйти.

# 5. Дополнительные экраны

## 5.1. AI-ассистент

### Назначение

Помочь пользователю понять и адаптировать утверждённый тренировочный трек.

### Быстрые сценарии

- сократить занятие;
- объяснить упражнение;
- заменить недоступное упражнение;
- подготовить к матчу;
- провести рефлексию после матча;
- объяснить недельный отчёт.

### Интерфейс

- чат;
- быстрые кнопки;
- контекст текущего занятия;
- отображение лимита запросов на Free / Plus;
- обратная связь на ответ.

### Ограничения

AI не должен:

- придумывать упражнения вне проверенной базы;
- гарантировать повышение рейтинга;
- давать непроверенные раскидки;
- утверждать точную причину ошибки без достаточных данных.

---

## 5.2. Уведомления

### Содержимое

- тренировка запланирована;
- пропущена тренировка;
- готов недельный отчёт;
- обновился FACEIT-профиль;
- получено достижение;
- скоро завершится трек;
- предложение продолжить следующий цикл.

---

## 5.3. Paywall

### Назначение

Показать платную ценность в контексте конкретного действия.

### Тарифы

#### Free

- один базовый трек;
- ограниченные карты;
- базовый прогресс;
- реклама;
- ограниченный AI.

#### Plus — 299 ₽/месяц

- без рекламы;
- полные треки;
- недельная адаптация;
- история;
- дополнительные карты;
- базовый AI.

#### Pro — 699 ₽/месяц

- ежедневная адаптация;
- расширенная аналитика;
- больше AI;
- несколько целей;
- углублённые программы;
- расширенные отчёты.

### Триггеры показа

- завершён бесплатный трек;
- пользователь открывает платную карту;
- исчерпан AI-лимит;
- пользователь хочет второй активный трек;
- пользователь открывает расширенный отчёт.

### Требование

Paywall должен объяснять результат, а не только перечислять функции.

---

## 5.4. Сообщить о проблеме

### Категории

- не запускается упражнение;
- неверная инструкция;
- устаревшее видео;
- ошибка FACEIT;
- проблема оплаты;
- ошибка AI;
- другое.

### Поля

- категория;
- описание;
- автоматическое приложение технического контекста;
- необязательный скриншот.

# 6. Рекомендуемая структура нижнего меню

# 8. Общие требования к UX

1. Пользователь должен начинать сегодняшнюю тренировку максимум за два нажатия после открытия приложения.
2. На каждом экране должно быть одно очевидное основное действие.
3. Инструкции должны быть короткими и понятными без просмотра полного видео.
4. Любое упражнение должно иметь вариант «не могу выполнить».
5. Пропуск дня не должен разрушать весь трек.
6. Приложение должно честно показывать источник данных и уровень уверенности в выводах.
7. Рейтинг нельзя использовать как единственное доказательство прогресса.
8. Реклама не должна прерывать активное упражнение.
9. Пользователь должен понимать, почему ему назначено каждое задание.
10. Тёмная тема является основной для MVP.

# 11. Основной пользовательский сценарий

1. Пользователь проходит onboarding.
2. Подключает FACEIT или вводит Premier.
3. Выбирает цель и режим тренировок.
4. Проходит benchmark.
5. Получает профиль навыков.
6. Система создаёт 14-дневный трек.
7. Пользователь открывает «Сегодня».
8. Выполняет упражнения.
9. Фиксирует результаты.
10. Получает Match Focus.
11. После матча оставляет короткую обратную связь.
12. Через неделю получает отчёт.
13. Система корректирует следующую неделю.
14. После завершения трека пользователь получает итог и предложение следующего цикла.
